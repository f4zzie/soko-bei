# Decisions

1. **MongoDB for accounts, Cassandra for prices (user instruction mid-build).** Users, OTP codes and refresh tokens live in MongoDB; all price data stays in Cassandra. A unique index on `users.phone` replaces the Cassandra LWT, so the app now has no LWT. V004 drops the superseded Cassandra tables (`users_by_*`, `otp_codes`, `refresh_tokens*`); no production data existed. The spec's Cassandra-only rules about those tables no longer apply to them.
2. **Cassandra schema additions.** V001 uses `IF NOT EXISTS` on every table (safe re-run after a half-applied migration; the runner also bootstraps `schema_migrations` itself). V003 added `flags_by_user` (find a user's flags on deletion without a scan). V003 also added `refresh_tokens_by_user`, later removed by V004.
3. **Idempotency check runs before age validation.** A retry of an already-stored report must return 200 even if it has since aged past 14 days, otherwise the phone would mark a synced report REJECTED. Payload mismatch still yields 409.
4. **OTP hashing:** HMAC-SHA256(server secret, salt + phone + code). OTP expiry uses real time (Mongo TTL index plus an explicit check), not the injectable business clock, because the TTL monitor uses server time.
5. **JWT time** uses the real clock, independent of `BusinessCalendar`, so tests can move business time freely.
6. **`kg` unit is `verified = true`** (1 kg = 1 kg). Every other seed factor is a placeholder with `verified = false`.
7. **Integration test infrastructure:** Testcontainers by default; `SOKO_TEST_CASSANDRA` / `SOKO_TEST_MONGO` point at external servers for machines without Docker. Each test gets its own Cassandra keyspace and Mongo database.
8. **Daily stats window** is `REPORT_MAX_AGE_DAYS + 1` days including today, so a report exactly 14 days old is covered.
9. **Admin rebuild** always also rebuilds the "latest" tables for today.
10. **Paging:** every list endpoint pages with an opaque base64 driver paging state. The final page can occasionally be empty with no token; clients loop until the token is null.
11. **Rate limits:** reports use Ktor's RateLimit plugin keyed by user id; OTP requests use an in-memory sliding window per phone (single-instance, see README).
12. **Versions:** latest stable at build time (Kotlin 2.4.21, Ktor 3.6.0, Cassandra driver 4.19.4, MongoDB Kotlin driver 5.13.0, Gradle 9.8.1).
13. **Conversion corrections policy.** Source reports keep their stored `kg_per_unit`, `conversion_version` and `price_per_kg_kes` forever; a new `commodity_units` version only applies to later reports. Rebuilds and daily stats use each report's stored `price_per_kg_kes`. Rejected alternative: recomputing history from the latest factor, which would silently move past medians and break the "raw values are immutable" rule.
14. **Admin API is closed when `ADMIN_TOKEN` is empty** (403 for every request, even an empty header). The token is compared as SHA-256 digests with `MessageDigest.isEqual` (constant time, no length leak).
15. **Startup guard.** With `DEV_MODE=false` the app refuses to start if `JWT_SECRET`/`OTP_SECRET` are a shipped default (including the compose and `.env.example` values) or under 32 characters, or `ADMIN_TOKEN` is set but under 32 characters. Checked in `module()` before any database connection.
16. **Account deletion across two stores.** Order: Cassandra first (anonymise source reports and locators via `reports_by_user`, then delete `reports_by_user` partitions and flags), MongoDB last (refresh tokens, OTP, then the user document). The user document is the "work remaining" marker, so a retry after a crash resumes safely; deleting an already-deleted account returns 204. `AccountService` has a no-op `afterCassandraPhase` hook used only by the crash-recovery test.
17. **Compose service renamed `mongodb`** (was `mongo`) so `docker compose up -d cassandra mongodb` works.
18. **Android `staging` build type** inherits `release` (`initWith`), so it has identical R8/shrink/keep rules, but is signed with the debug keystore, uses `applicationIdSuffix=".staging"` and takes its URL from `-PsokoBaseUrl` (default `http://localhost:8080`, meant for `adb reverse`). Gradle properties were renamed to `sokoDebugBaseUrl`, `sokoBaseUrl`, `sokoReleaseBaseUrl`.
19. **Cleartext policy.** One `network_security_config_dev.xml` for debug and staging: base config forbids cleartext, a single `domain-config` allows it for `localhost` and `10.0.2.2` (no subdomains). Release has a config with cleartext forbidden everywhere. The old debug config allowed cleartext to every host; that was tightened. `usesCleartextTraffic` is `false` for all build types (the network security config takes precedence on API 24+, minSdk is 26).
20. **Release URL guard.** `verifyReleaseBaseUrl` runs before `assembleRelease`, `bundleRelease` and `packageRelease` and fails on the placeholder or a non-https URL. Because a plain `build` must not fail for developers, `assemble` (hence `build`) is wired to debug and staging only; release is always built explicitly. Rejected: enforcing the check on `build`, which would force a URL on every developer build, or not guarding at all, which allows shipping the placeholder.
21. **Cleartext proof for release** is two independent checks: a JVM unit test over the XML configs and a `verifyReleaseNetworkSecurity` task over the merged release manifest (part of `check`).
