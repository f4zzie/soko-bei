# Decisions

1. **MongoDB for accounts, Cassandra for prices (user instruction mid-build).** Users, OTP codes and refresh tokens live in MongoDB; all price data stays in Cassandra. A unique index on `users.phone` replaces the Cassandra LWT, so the app now has no LWT. V004 drops the superseded Cassandra tables (`users_by_*`, `otp_codes`, `refresh_tokens*`); no production data existed. The spec's Cassandra-only rules about those tables no longer apply to them.
2. **Cassandra schema additions.** V001 uses `IF NOT EXISTS` on every table (safe re-run after a half-applied migration; the runner also bootstraps `schema_migrations` itself). V003 added `flags_by_user` (find a user's flags on deletion without a scan). V003 also added `refresh_tokens_by_user`, later removed by V004.
3. **Idempotency check runs before age validation.** A retry of an already-stored report must return 200 even if it has since aged past 14 days, otherwise the phone would mark a synced report REJECTED. Payload mismatch still yields 409.
4. **OTP hashing:** HMAC-SHA256(server secret, salt + phone + code). OTP expiry uses real time (Mongo TTL index plus an explicit check), not the injectable business clock, because the TTL monitor uses server time.
5. **JWT time** uses the real clock, independent of `BusinessCalendar`, so tests can move business time freely.
6. **`kg` unit is `verified = true`** (1 kg = 1 kg). Every other seed factor is a placeholder with `verified = false`.
7. **Integration test infrastructure:** Testcontainers by default; `SOKO_TEST_CASSANDRA` / `SOKO_TEST_MONGO` point at external servers for machines without Docker. Each test gets its own Cassandra keyspace and Mongo database.
8. **Daily stats window** is `REPORT_MAX_AGE_DAYS + 1` days including today, so a report exactly 14 days old is covered.
9. **Admin rebuild** always also rebuilds the "latest" tables for today.
10. **Paging:** every list endpoint pages with an opaque base64 driver paging state. The final page can occasionally be empty with no token; clients loop until the token is null.
11. **Rate limits:** reports use Ktor's RateLimit plugin keyed by user id; OTP requests use an in-memory sliding window per phone (single-instance, see README).
12. **Versions:** latest stable at build time (Kotlin 2.4.21, Ktor 3.6.0, Cassandra driver 4.19.4, MongoDB Kotlin driver 5.13.0, Gradle 9.8.1).
13. **Conversion corrections policy.** Source reports keep their stored `kg_per_unit`, `conversion_version` and `price_per_kg_kes` forever; a new `commodity_units` version only applies to later reports. Rebuilds and daily stats use each report's stored `price_per_kg_kes`. Rejected alternative: recomputing history from the latest factor, which would silently move past medians and break the "raw values are immutable" rule.
14. **Admin API is closed when `ADMIN_TOKEN` is empty** (403 for every request, even an empty header). The token is compared as SHA-256 digests with `MessageDigest.isEqual` (constant time, no length leak).
15. **Startup guard.** With `DEV_MODE=false` the app refuses to start if `JWT_SECRET`/`OTP_SECRET` are a shipped default (including the compose and `.env.example` values) or under 32 characters, or `ADMIN_TOKEN` is set but under 32 characters. Checked in `module()` before any database connection.
16. **Account deletion across two stores.** Order: Cassandra first (anonymise source reports and locators via `reports_by_user`, then delete `reports_by_user` partitions and flags), MongoDB last (refresh tokens, OTP, then the user document). The user document is the "work remaining" marker, so a retry after a crash resumes safely; deleting an already-deleted account returns 204. `AccountService` has a no-op `afterCassandraPhase` hook used only by the crash-recovery test.
17. **Compose service renamed `mongodb`** (was `mongo`) so `docker compose up -d cassandra mongodb` works.
18. **Android `staging` build type** inherits `release` (`initWith`), so it has identical R8/shrink/keep rules, but is signed with the debug keystore, uses `applicationIdSuffix=".staging"` and takes its URL from `-PsokoBaseUrl` (default `http://localhost:8080`, meant for `adb reverse`). Gradle properties were renamed to `sokoDebugBaseUrl`, `sokoBaseUrl`, `sokoReleaseBaseUrl`.
19. **Cleartext policy.** One `network_security_config_dev.xml` for debug and staging: base config forbids cleartext, a single `domain-config` allows it for `localhost` and `10.0.2.2` (no subdomains). Release has a config with cleartext forbidden everywhere. The old debug config allowed cleartext to every host; that was tightened. `usesCleartextTraffic` is `false` for all build types (the network security config takes precedence on API 24+, minSdk is 26).
20. **Release URL guard.** `verifyReleaseBaseUrl` runs before `assembleRelease`, `bundleRelease` and `packageRelease` and fails on the placeholder or a non-https URL. Because a plain `build` must not fail for developers, `assemble` (hence `build`) is wired to debug and staging only; release is always built explicitly. Rejected: enforcing the check on `build`, which would force a URL on every developer build, or not guarding at all, which allows shipping the placeholder.
21. **Cleartext proof for release** is two independent checks: a JVM unit test over the XML configs and a `verifyReleaseNetworkSecurity` task over the merged release manifest (part of `check`).
22. **Anchored ignore rules.** `.gitignore` and `.dockerignore` list the real Gradle output directories by path instead of a bare `build/`, because a bare pattern also matches source packages named `build`. `scripts/check-ignored-sources.sh` (run first in CI with `REQUIRE_DOCKER=1`) fails if any source-type file is ignored by either file.
23. **Repository initialised locally, no remote.** The working directory was not a git repository. History starts at `5d48219`; nothing was pushed because no remote exists, and creating a GitHub repository was not requested. The README badge uses an `OWNER/REPO` placeholder until one exists.
24. **CI shape.** Five jobs on ubuntu-latest: checks, backend (Testcontainers), android (check, debug, staging, then release with an explicit https URL), smoke (compose with dev defaults only), instrumented (reactivecircus emulator runner, API 34, google_apis x86_64, pixel_5, 2048 MB, AVD snapshot cache, KVM enabled). Android SDK licenses are accepted in the backend job too because Gradle always configures `:android`. Compose is started with `--wait`.
25. **Instrumented tests avoid Hilt** and build their own in-memory database and fakes; the Compose test uses `createComposeRule` v1 to match the Robolectric test (deprecated in favour of v2). The one run that reported zero tests is recorded as unexplained rather than hidden.
26. **Device checklist** treats "no network" (airplane mode) and "network present, backend unreachable" as separate cases, because `adb reverse` carries the app's traffic over USB and airplane mode alone may not cut it off.
27. **`/health` empty reply was a startup race, not an app bug.** Reproduced with `curl -sv` right after `docker compose up`: "Empty reply from server" / "Connection reset by peer" for about a minute, because docker-proxy accepts the connection before the JVM (still running migrations) listens. The backend service had no healthcheck, so `--wait` returned as soon as the container started. Fix: a compose healthcheck (`curl -sf /health`, 200 only when both stores answer). The handler logic moved to `healthReport()`, which always returns a JSON body with a status per database (200 healthy, 503 otherwise), unit-tested in `HealthReportTest`.
28. **README follows the structure of the author's other project** (title and badges, one-command start, contents, background, features, data design, getting started, configuration, testing, structure, limitations). It has no screenshots section because the app has not been screenshotted; none are invented.
29. **Screenshots are real captures of the debug build**, taken with `adb exec-out screencap` on the API 34 emulator against the compose backend, after submitting about 20 demo reports through the API (marked "demo data" in the README). `demo.gif` is a slideshow of those same captures, not a screen recording. The README has no "live demo" line because nothing is deployed.
30. **README CI wording relies on the badge.** Run counts and run ids go stale on every push, so the README points at the badge and says flakiness is checked by rerunning; the count of consecutive green runs is recorded only in PROGRESS.md.
31. **`.env` is optional for compose.** Verified from a fresh `git clone` (no `.env`, which is gitignored): `docker compose up -d --build --wait` reaches all three services healthy and `scripts/smoke-test.sh` passes, because every variable has a default in `docker-compose.yml`. The README now says so and keeps `cp .env.example .env` only as the way to override values.
32. **Phone privacy is proved by `PrivacyIT`, a black-box string scan** of every read endpoint's body (anonymous and as another user, plus 404 bodies) for the three phone formats. There was no such test before (only the log-redaction test). `/v1/me` returns the caller's own `phone_masked`, which is by design. Proved sensitive by injecting a leak into `/health` (test failed naming the path), then reverting.
33. **Wireless demo uses a Cloudflare quick tunnel and a baked-in staging URL.** `scripts/demo-up.sh` owns one tunnel process, builds and verifies the APK, copies it to the human user's Desktop and waits. Its signal handler stops only that tunnel; `--down` additionally stops compose without deleting volumes. Cloudflared installs only under `~/.local/bin`; generated URLs, APKs and runtime logs stay outside tracked files. A new quick-tunnel URL requires a fresh build and reinstall.
34. **An explicit empty compose admin token must remain empty.** `${ADMIN_TOKEN-dev-admin-token}` preserves the existing unset dev default while allowing the demo's exported empty value to close every admin route. Production config defaults and startup-guard checks are unchanged. `/health` now exposes the effective `dev_mode` boolean so the seeder can refuse a non-dev backend before authentication or writes.
35. **Seed through the public report API with a date-keyed fixed seed.** Five fixed dev logins accept consent and submit 30 reports each, covering every market/commodity today plus two historical samples per pair over 12 Nairobi days. UUIDs and payloads are identical for the same `DEMO_DATE`; a new date creates a fresh dataset. Direct dev OTP verification avoids the OTP-request quota. The launcher recreates the backend to reset in-memory quotas; standalone seeding honours a report's `Retry-After` once, with a renewed login, instead of increasing production limits.
36. **Daily trends update on accepted submissions, including historical reports.** Recompute the affected day from immutable source reports immediately; scheduled rebuilds still reconcile it. This prepares real seeded charts with the admin API continuously closed and also makes newly synced late reports visible without waiting for the nightly job. The existing late-report integration test now also asserts the pre-job daily value and trend, retaining all its rebuild assertions.
37. **MongoDB image is overridable for kernel compatibility.** `docker-compose.yml` uses `${MONGO_IMAGE:-mongo:8}`. CI's compose smoke job and the verified local demo select `MONGO_IMAGE=mongo:7.0` after the runner reported SERVER-121912. Existing MongoDB 8.3 data cannot be opened by 7.0; changing the image is not a data migration, and seeding only reconstructs the demo dataset. Retain existing volumes and use compatible storage or a supported migration when changing database versions.
38. **Demo tunnel prefers HTTP/2 so it does not depend on QUIC/UDP.** `cloudflared` runs with `--protocol http2`, using a TCP connector; outbound access to Cloudflare's tunnel service is still required. The quick-tunnel URL is baked into the staging APK, so a fresh tunnel URL always requires a rebuild and reinstall.
39. **Use one CI MongoDB image override for both database test paths.** Testcontainers now reads `MONGO_IMAGE`, with `mongo:8.0` retained as its unset default; CI selects `mongo:7.0` for both Testcontainers and compose. Resolve Mongo container startup before allocating a per-test Cassandra keyspace, and protect database preparation with resource cleanup. Keep all assertions and print full failure exceptions. The complete backend suite gets a 45-minute step inside a 50-minute job, leaving time for the always-run report upload; a 25-minute step proved too short, and the first successful corrected CI job took 25m55s.
40. **Expand the running demo additively, with backups and a fixed tunnel.** The large dataset is dev-only and must not change V001–V004 or remove existing catalog/report/account data. Snapshot Cassandra and dump MongoDB before loading, fingerprint existing rows, and verify them afterwards. Keep MongoDB 7.0 and the existing tunnel process/URL; a backend-only deployment can use that tunnel. Replace the Desktop APK only if an observed UI problem requires an app change, building against the same URL.
41. **Keep historical import on the report domain path.** A separately guarded `demo-backfill` CLI assembles the existing `Services` with a widened age window, deferred per-report recomputation and additive-only aggregate rebuilding; ordinary HTTP wiring retains all defaults. Each generated report still traverses normal account/consent checks, `ReportValidator`, versioned conversion, `TimeUuids.forReport` and the logged three-table write batch. The CLI connects to the existing schema without migration. Batch defaults are 64 pending/two in flight; derived history is rebuilt by the existing service for the entire selected range, including an all-duplicate recovery run.
42. **Treat the catalog and scenario as versioned demo fixtures.** Ten real market locations and eight bilingual commodities are applied with `IF NOT EXISTS`, then checked for conflicts; all 25 added unit factors are deliberately `verified=false`. Seed/date/market/commodity/ordinal identify immutable generated payloads. Keep seed 42 and the same catalog/conversions when replaying a range; a different seed intentionally describes different reports. Per-commodity base levels, origin-sensitive market multipliers, slow seasonal curves, weekday volume, closed days, three week-long commodity shocks and about 1% extra-zero outliers are synthetic demonstration choices, not agricultural field measurements. Flags annotate some outliers but retain the existing median algorithm.
43. **Feed today over HTTPS with normal limits.** The backend's plan reserves 40 clearly labelled synthetic accounts and a 270-pair opening board; at most 1,000 elapsed-time reports are sent through the live public API, leaving room under 30 reports/hour/user for the trickle. A private shared local ledger counts attempts conservatively, including retries, and honors server `Retry-After`; no JWT or concrete tunnel URL is persisted in that ledger. The 20–40-second trickle uses the same day's price templates, rotates accounts and retries an identical UUID/payload. Mongo demo markers protect account identity and refuse adoption of an unmarked existing account. Device My reports remains its local submission history.
44. **Make long trends readable without hiding extreme prices.** The original installed APK's 90-day tomato chart compressed the median against a roughly KES 1,538/kg outlier. Add a default, explicitly labelled median-focus scale with numeric KES/kg ticks and a full-range toggle. The focused min/max band is clipped visibly with a disclosure; period low/high and the underlying data remain exact. Position points by calendar day so sparse dates do not imply uniform reporting; reduce dots on longer series. This observed chart problem justifies an incremental staging rebuild against the existing tunnel URL and an in-place APK update.
45. **Use EC2 and the existing Caddy for the permanent presentation endpoint.** `sokobei.duckdns.org` points at the existing Elastic IP. The Soko backend joins `agri_app_default` as `soko-backend`; only Caddy publishes 80/443. No Soko backend/database host ports and no competing reverse proxy. Preserve AgriTrack's site, containers and volumes; do not reuse its Android/CLI-blocking user-agent matcher on Soko. Build images off-instance and generate catalog/history/current prices on EC2, not from laptop database exports.
46. **Size the shared host before loading data.** The initial micro-instance import exhausted memory and disrupted both sites; recover AgriTrack, then use the user-approved 50 GB root volume and `t3.medium` (4 GB RAM). Cassandra heap 1 GB, Mongo cache 0.5 GB, backend heap 512 MB and 7 GB total swap are presentation limits, not a production sizing guarantee. Keep the retained named volumes and use additive deterministic replay. CLI `--output` paths are container-local; copy the completed summary with `docker cp`.
47. **Supervise demo refreshes and private seven-day backups with systemd.** Hourly HTTPS today-feeds plus a restartable 20–40-second trickle share the normal quota ledger and regenerate on the EAT date boundary. Daily Cassandra snapshot archives/Mongo dumps run around 03:00 EAT, with private staged files, integrity manifests and seven-day retention; clear only the successfully exported snapshot. A validated archive is not a restore rehearsal. Keep dev authentication and empty admin token explicit; the smoke script preserves an explicitly empty token and expects 403 instead of attempting an enabled rebuild. Use a dedicated synthetic smoke phone because the suite deletes its account.
48. **Defer SSH restriction only by explicit user choice.** The user selected “Leave SSH for now” rather than supplying a confirmed public IP. TCP 22 therefore remains open to `0.0.0.0/0`; document this as an unresolved security exception, not as completed hardening. Never guess a `/32` or risk locking out the user.
